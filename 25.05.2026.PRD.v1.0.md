## 1. Business Overview

**SheGlow** is a B2C Egyptian e-commerce store selling women's hand accessories and jewellery (bracelets, necklaces, rings, chains, anklets, earrings). Target market: Egyptian women aged 18–40.

- **Currency**: EGP (Egyptian Pounds) — all prices, fees, totals
- **Language**: English UI
- **Geography**: Egypt only — 27 governorates, each with its own shipping fee
- **Business model**: Direct sales with Cash on Delivery as primary payment. Card (PayMob), InstaPay, and Vodafone Cash also supported
- **Contact channels**: WhatsApp floating button, Instagram link, contact form

## 4. Data Models

### 4.1 `accounts.User` (custom auth user)

```python
USERNAME_FIELD = 'phone'
REQUIRED_FIELDS = ['first_name', 'last_name']

phone       = CharField(max_length=20, unique=True)   # primary identifier
email       = EmailField(blank=True, null=True)        # optional
first_name  = CharField (inherited from AbstractUser)
last_name   = CharField (inherited from AbstractUser)
is_active, is_staff, is_superuser  (inherited)
```

- Egyptian phone validation: 11 digits starting with `01`
- `user.full_name` property → `"{first} {last}".strip() or phone`
- `UserManager.create_user(phone, password, **extra_fields)`
- `UserManager.create_superuser(phone, password, **extra_fields)`

## 6. Template System

All templates extend `templates/base.html`.

### `base.html` provides:

- `<head>`: Open Graph meta blocks (`og_title`, `og_description`, `og_image`), SVG favicon, Google Fonts (Cormorant Garamond + Inter), Tailwind CDN with custom config, Alpine.js CDN
- **Navbar**: sticky, logo, desktop nav (Home, Shop, Categories dropdown via `{% load_categories %}`), search icon, wishlist badge, cart badge, Login/Create Account (guests) or profile link (authenticated)
- **Live search dropdown**: triggered by search icon, Alpine.js `appState()`, debounced 300ms, calls `/api/search/?q=`, shows results after 4 chars typed, `@keydown.enter` → `/search/?q=`
- **Toast notifications**: `showToast(message, type)` global JS function
- **Footer**: brand, quick links, policy links, WhatsApp + Instagram social icons; includes **Track Order** link (`/track/`)
- **WhatsApp floating button**: bottom-right, links to `WHATSAPP_NUMBER`
- **Global JS functions**: `addToCart(productId, event)`, `toggleWishlist(productId, btn)`, `getCsrf()`, `updateCartBadge(count)`, `updateWishlistBadge(count)`
- **Alpine.js `appState()`**: `mobileMenuOpen`, `searchOpen`, `searchQuery`, `searchResults`, `searchLoading`, `searchNoResults`, `doSearch()`, `closeSearch()`

### Context Processors (auto-available in all templates):

```python
# sheglow/context_processors.py
site_settings  → WHATSAPP_NUMBER, INSTAGRAM_URL, SITE_NAME, SITE_TAGLINE
cart_count     → cart_count (integer)
wishlist_context → wishlist_ids (set of product IDs), wishlist_count (integer)
```

### Template Tags (`{% load product_tags %}`):

```python
{% load_categories %}          # inclusion tag → nav_categories.html
{% load_categories_mobile %}   # inclusion tag → nav_categories_mobile.html
{{ value|currency }}           # filter → "1,234 EGP"
```

## 7. Implemented Features

### ✅ Phase 1 — Foundation

- Django project setup with custom `User` model
- `products` app: Category, Product, ProductImage models
- `products/admin.py`: full admin with image upload, list_editable fields, inline images
- Home page: featured products + new arrivals + category grid
- Product list page: filtering (category, price, badge), sorting, pagination (12/page)
- Product detail page: image gallery, add to cart, wishlist toggle, related products
- Custom 404 page
- Base template with navbar, footer, toast system

### ✅ Phase 2 — Commerce

- **Cart**: DB-backed per user (OneToOne) or per session (session_key); `get_or_create_cart()`, `merge_carts()` on login
- **Checkout**: multi-field form, guest + authenticated, pre-fills from profile, promo code, receipt upload
- **Orders**: `Order` model with full status lifecycle, `OrderItem`, `PaymentReceipt`
- **Payment methods**: COD, InstaPay (upload receipt), Vodafone Cash (upload receipt), PayMob card (full 3-step API integration, HMAC callback)
- **Order history**: `/orders/` list, `/orders/<num>/` detail with status progress bar
- **Order confirmation**: accessible without login (for guest orders)
- **Promo codes**: percentage or fixed, date validity, usage limit, min order amount
- **Admin**: full order admin with `list_editable`, `OrderItemInline`, `PaymentReceiptInline`
- **Seed data**: `python manage.py seed_data`

### ✅ Phase 3 — UX & Ops

- **Wishlist**: AJAX heart toggle on product cards/detail, `/wishlist/` page, badge count in navbar
- **Contact form**: `ContactMessage` model, DB-backed, admin read/unread
- **Static pages**: Privacy Policy, Refund Policy, Terms, Shipping Policy
- **Settings split**: `base.py / dev.py / prod.py`
- **Docker**: `Dockerfile` + `docker-compose.yml` (postgres:16-alpine + gunicorn)
- **WhiteNoise**: static file serving with compression + caching
- **SVG favicon** in `<head>` + `/favicon.ico` → 204 response

### ✅ Phase 4 — Search, Auth, Shipping, Admin Tools, Analytics

- **4.1 Live search**: AJAX `/api/search/?q=`, Alpine.js dropdown in navbar, debounced 300ms, triggers at 4 chars, Enter → full search page
- **4.2A Phone-first auth**: `USERNAME_FIELD = 'phone'`, Egyptian mobile validation (11 digits, starts `01`), custom `UserManager`
- **4.2B Separate Login/Create Account buttons** in navbar for guests
- **4.2C Feminine account page**: gradient bg, avatar initials, 4 KPI stats (orders, wishlist, active orders, total spent), recent orders list, wishlist preview grid, profile edit form, quick actions panel
- **4.3 Governorate shipping fees**: `ShippingZone` model, 27 zones seeded, AJAX fee update on checkout governorate change, shows delivery days estimate
- **4.4A Excel export**: `export_orders_excel` admin action → `.xlsx` with pink headers, auto-sized columns
- **4.4B PDF invoice**: `/orders/<num>/invoice/` → ReportLab A4 PDF, rose-branded; "Download Invoice" button on order detail
- **4.4C Manual order creation in admin**: writable `OrderItemInline`; `save_related()` auto-fills product_name/price/subtotal, recalculates totals, decrements stock
- **4.5A Sales dashboard**: `/admin-panel/analytics/sales/` — Chart.js line chart (daily revenue), doughnut (payment method), top products, top governorates, 4 KPI pills, period selector
- **4.5B Inventory dashboard**: `/admin-panel/analytics/inventory/` — out-of-stock, low-stock (≤10), best sellers (60 days)

### ✅ Enhancement Batch — Post-Phase 4

- **E1 Cart AJAX stepper**: Cart page fully reactive with Alpine.js. Qty `+`/`−` update via AJAX without page reload. Optimistic UI, rollback on error. `+` button disabled when `qty >= stock`. Items initialized from `cart_items_json` server-side JSON.
- **E2 Out-of-stock UI**: "Add to Cart" button replaced with "Out of Stock" (disabled, gray) when `product.stock == 0` on product detail and product cards.
- **E3 Password reset**: Full forgot-password flow using Django's built-in `PasswordResetView` et al. Email with reset link. 4 templates. "Forgot password?" link on login page. Requires email configured in `.env`.
- **E4 Order confirmation email**: Sent automatically on order creation via `send_order_confirmation_email(order, request)`. Plain text + HTML (rose-branded). Wrapped in `try/except` — never blocks order creation. Templates: `accounts/emails/order_confirmation.txt` + `order_confirmation_html.html`.
- **E5 Order cancellation**: "Cancel Order" button on `/orders/<num>/` for `pending` or `confirmed` orders. Alpine.js two-step confirmation dialog. POST to `/orders/<num>/cancel/`. Restores product stock on cancel. View: `cancel_order` (`@login_required @require_POST`).
- **E6 Product reviews & star ratings**: `Review` model (unique per user+product, admin-approved). Submit form on product detail — only visible to users who have a delivered/confirmed order for that product. Alpine.js interactive star picker. Avg rating display. Reviews list with user avatar initials and date. Pending-review notice if user already submitted. Login prompt for guests.
- **E7 Homepage Banner CMS**: `pages.Banner` model — admin-editable title, subtitle, buttons, badge text, optional background image. `home` view passes `hero_banner` (first active banner). Template falls back to hardcoded content if no active banner. With image: full-bleed dark hero. Without image: gradient blobs + product showcase card.
- **E8 Guest order tracking**: Public page at `/track/`. Enter order number + phone number to look up any order (no login required). Shows status stepper, shipping info, items with images, totals. Error message for wrong credentials. Login prompt at bottom.
- **E9 WhatsApp share button**: On product detail page, next to the wishlist button. Links to `https://wa.me/?text=<product name> - <full URL>`. Opens WhatsApp share sheet. Green hover color.
- **E10 Sitemap + robots.txt**: `/sitemap.xml` — includes `ProductSitemap` (all active products, weekly, priority 0.8), `CategorySitemap` (all active categories, weekly, 0.7), `StaticSitemap` (home/shop/search, monthly, 0.5). `/robots.txt` — disallows admin, accounts, cart, checkout, orders, admin-panel; includes Sitemap directive.
- **E11 Per-product SEO + JSON-LD**: `meta_title` and `meta_description` fields on `Product` model (blank=True). If filled, used in `<title>` and `<meta name="description">` overriding defaults. JSON-LD `Product` schema injected in `<script type="application/ld+json">` on every product detail page, including `aggregateRating` when reviews exist.

## 9. Key Conventions & Patterns

### Authentication
- `@login_required` redirects to `LOGIN_URL = '/accounts/login/'`
- `@staff_member_required` (analytics) redirects to `/admin/login/`
- Guest cart merges into user cart on login automatically
- Password reset requires `User.email` to be set — the reset link is emailed to `user.email`

### AJAX Pattern
- All AJAX endpoints return `JsonResponse`
- Cart actions send `X-CSRFToken` header; CSRF token read from `getCsrf()` in base.html JS
- Wishlist toggle: POST to `/wishlist/toggle/<id>/`; unauthenticated → `{redirect: '/accounts/login/?next=...'}`

### Cart Behavior
- Authenticated: `Cart.objects.get_or_create(user=request.user)`
- Guest: `Cart.objects.get_or_create(session_key=session_key, user=None)`
- On login: `merge_carts(user, session_key)` — adds guest items to user cart (capped at product stock)
- Cart page uses Alpine.js `x-data` initialized from `cart_items_json` (server-rendered JSON); qty updates are AJAX, no page reload

### Checkout Shipping Fee
- `orders.views.get_shipping_fee(governorate)` → queries `ShippingZone`, falls back to `settings.DEFAULT_SHIPPING_FEE`
- On page load: pre-filled from user profile governorate
- Live update: Alpine.js `@change` on governorate select → fetch `/checkout/shipping-fee/?governorate=X`

### Order Number Format
- `SG-YYYYMMDD-NNNN` (e.g., `SG-20260525-0001`)
- Sequential per day, zero-padded to 4 digits

### PDF Invoice
- ReportLab, A4, rose-branded (`#F43F5E`)
- Served inline (opens in browser tab), filename: `invoice-<order_number>.pdf`
- Accessible to order owner or staff

### Admin Excel Export
- `openpyxl` action on `OrderAdmin`
- Pink header row (`#FFB3C6`)
- Auto-sized columns (capped at 60 chars)
- Filename: `sheglow_orders.xlsx`

### Email
- `send_order_confirmation_email(order, request)` in `orders/views.py` — always wrapped in `try/except`, never blocks
- Uses `EmailMultiAlternatives` with plain text + HTML parts
- `render_to_string` for template rendering
- In dev: `EMAIL_BACKEND = console` → emails print to terminal
- In prod: set `EMAIL_BACKEND = django.core.mail.backends.smtp.EmailBackend` + SMTP credentials

### Product Reviews
- Only purchasers (delivered or confirmed `OrderItem`) can submit
- `Review.objects.update_or_create(product=product, user=request.user, ...)` — one review per user per product
- `is_approved=False` by default; admin approves in `ReviewAdmin`
- `product_detail` view computes `avg_rating` (Avg) and `review_count` (Count) from approved reviews only

### SEO
- `meta_title` / `meta_description` on `Product` override `<title>` and `<meta description>` if non-empty
- JSON-LD `Product` schema on product detail includes `aggregateRating` only if `review_count > 0`
- Sitemap auto-updates from DB (product `updated_at` as `lastmod`)

### Governorates
- Defined in `accounts/models.py` as `EGYPTIAN_GOVERNORATES` (list of `(value, label)` tuples)
- 27 governorates, values are English names (e.g., `'Cairo'`, `'Giza'`)
- Used as `choices` on `Customer.governorate` and on `Order.governorate`
- `ShippingZone.governorate` values match the same English names

### Product Badges
- Choices: `''` (none), `'new'`, `'sale'`, `'bestseller'`, `'limited'`
- CSS classes: `.badge-new`, `.badge-sale`, `.badge-bestseller`, `.badge-limited`

### Template Loading
- All templates live in `/templates/` (project-level `DIRS`)
- `APP_DIRS = True` so app-level templates also work, but none are used currently

## 14. Known Issues & Notes

1. **Search consistency** *(fixed)*: Both the API (`/api/search/`) and the navbar JS now trigger at ≥ 2 characters. Previously the API accepted ≥ 2 chars but the JS only fired at ≥ 4, causing the dropdown to stay empty for short queries like "ri" or "go". All four JS threshold checks in `base.html` updated.

2. **Guest order detail** *(fixed)*: Guests who checked out without an account now see a "Want to check your order status later?" panel on the order confirmation page with a direct link to `/track/`. The login page also shows a "Track your order without logging in →" hint when redirected from an orders URL (`?next=/orders/...`). Previously there was no signpost to `/track/` after checkout.

3. **PayMob**: Integration is complete but disabled by default (`PAYMOB_ENABLED=False`). Enable by setting real credentials in `.env`.

4. **Stock concurrency** *(fixed)*: Stock decrement and increment now use `F('stock')` expressions — checkout, cancellation, and admin manual orders. SQL `UPDATE SET stock = stock - qty` is atomic at DB level.

5. **`DEFAULT_SHIPPING_FEE`**: Used as fallback when a governorate has no `ShippingZone` record or zone is inactive. Correct behavior — no fix needed.

6. **Manual order creation in admin**: Stock is decremented once via `save_related`. Re-saving does NOT decrement again (the `not change` guard). Intentional.

7. **Analytics redirect** *(fixed)*: Custom `staff_required` decorator in `analytics/views.py` — unauthenticated → `/accounts/login/?next=<path>`, non-staff → `/` with flash message.

8. **Decimal serialization in analytics** *(fixed)*: `daily` and `by_payment` dicts now have `revenue` converted to `float()` in Python before `json.dumps()`. The JS Chart.js datasets use `d.revenue` directly — no `parseFloat()` needed. `DjangoJSONEncoder` is no longer imported; `default=str` handles the remaining `datetime` field in `daily`.

9. **Password reset** *(fixed)*: `PhonePasswordResetForm` accepts phone number, looks up user, validates email on file, generates and sends token. Clear errors for unknown phone and no-email accounts.

10. **Reviews only for purchasers**: `user_purchased` requires `status__in=['delivered', 'confirmed']`. Intentional — prevents reviewing before confirmed receipt.

11. **Banner fallback**: No active `Banner` → hardcoded gradient hero. Correct behavior.

12. **Sitemap domain**: Uses `request.get_host()` — correct in production automatically. No Sites framework needed.
